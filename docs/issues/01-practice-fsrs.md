# 解答保存にFSRS・成長イベントを接続し、既存履歴から学習状態を引き継ぐ

> GitHub Issue: [#314](https://github.com/woodnx/iQbe/issues/314)。Q17〜Q20の改訂内容をGitHubへ反映・照合済み。

## 背景と到達点

競技クイズアプリiQbeで、解答履歴を保存するだけでなく、次の復習期限と成長の成果を更新したい。日替わりの「今日の5問」、スマート復習、成長画面が共通して使う解答記録の基盤を完成させる。

同じ解答の再送では履歴・習熟状態・成果を増やさず、別の実際の解答は同じ秒・同じ問題でも区別する。初期からFSRSを用い、過去履歴を引き継ぐ。ここでいう「定着」は推定であり、当日の全問正解とは別の意味である。

## 確定した学習ルール

- 判定は `0=不正解、1=正解、2=スルー` を維持。検索専用の `3=未解答` は保存しない。
- 不正解・スルーはFSRSのAgain、正解はGoodへ対応させる。Hard/Easyの入力は追加しない。
- 初回・同日・期限前の解答もFSRSに渡す。正解済みという理由で後の実際の解答を捨てない。
- 既存作業の設定を継承する。目標保持率90%、学習・再学習ステップ1分、初期の既定重み、間隔のランダムな揺らぎなし。算法の詳細と保存形式は外側のアダプターに置く。
- 定着推定は「評価時点から30日後の想起確率が90%以上、かつ長期復習段階」。現在値は評価時刻で再計算する。保存済み `RETAINED` の行数を現在の定着数にはしない。
- 同じユーザー・問題への並行解答はサーバーで処理順を確定して直列化する。クライアントの時計で並べ替えない。解答履歴とFSRSへ同じ確定時刻を渡し、既存の秒精度・日時互換性を守る。

## 成長イベント

イベントは解答直前の履歴・状態に対してサーバー側で判定する。

| 種類              | 成立条件                                             |
| ----------------- | ---------------------------------------------------- |
| `FIRST_CORRECT`   | そのユーザーがその問題に初めて正解した               |
| `REVENGE_SUCCESS` | 直前の解答が不正解またはスルーで、今回正解した       |
| `REVIEW_SUCCESS`  | 解答直前に既存の復習期限が到来しており、今回正解した |

- 初回解答の問題は、解答後に作られた期限を使って復習成功にしない。
- 同日の解き直し、自由演習、スマート復習、日替わりセットに同じ定義を使う。
- 一つの解答で複数のイベントが成立してよい。例：初回不正解から1分後に初めて正解すると、3種類すべて成立し得る。
- 集計に使えるよう、イベント種別・対象ユーザー・問題・確定解答ID・発生時刻を永続化する。同一解答の同一種類を重複保存しない。
- 問題削除時は現在の履歴と同様に成長イベントも削除し、過去の集計から除く。日替わりの対象外情報や、再送の二重処理を防ぐ記録とは区別する。

## 当日初回と後続解答を区別する記録

将来の「直近・平均の押した位置」では、そのユーザー・問題・JST日付における最初の解答が正解だった場合だけを対象にする。スマート復習で不正解から解き直して正解した押し位置を、最初から答えを思い出せたときの記録に混ぜないためである。

- 初回はサーバーが確定したJST学習日と全モード共通の解答順で判定する。自由演習・今日の5問・スマート復習を区別して日別の初回をリセットしない。
- 解答のモード、JST学習日、当日何回目か（または当日初回の識別）、該当する学習回・対象項目との関係を保存し、後から照合できるようにする。復習回の初回と、日別集計の初回は別の概念。
- 不正解・スルーからの解き直しだけでなく、最初に正解した後の同日2回目以降の解答も、押した位置の集計から除く。各解答は履歴・FSRS・条件を満たす成長イベントには通常どおり反映する。
- 初回の判定・順番の確定も履歴保存と同じトランザクション内で行い、同時解答の両方が初回にならないようにする。再送は元の識別情報を返し、日付変更後の再送でも新しい日の初回に数え直さない。
- `FIRST_CORRECT` はその問題への生涯初めての正解であり、今回の「当日初回の解答が正解」とは別。既存イベントを初回識別の代用にしない。
- 現行の `pressedWord` はUTF-16コード単位で数えた表示済み問題文の長さ。`0` は有効な位置、`-1` と既存の `null` は位置不明なので押し位置の対象外。判定が正解でも位置不明はあり得る。
- 現行の保存先は `histories.pressed_word`。`answer_logs.pressed_length` と取り違えない。既存値を別の文字数単位へ無断で読み替えない。
- 取得できた押し位置は中断・終了・再送でも保持する。現行の演習終了経路には一律 `-1` を送る箇所があるため、今回の記録経路を統合する際に確認する。
- 既存履歴にはモード・復習回の情報がない。これらは不明として扱う。当日初回の順序は保存済み履歴の日時と独立IDで安定して再現できる範囲で算出し、判断不能な情報を通常解答として捏造しない。
- 初回等の識別が不明な解答や位置不明の解答を、将来の初回正解の押し位置集計へ黙って含めない。表示用API・平均の計算・画面は後続とし、このIssueでは識別と元の押し位置を保存する。

APIにモード・復習回・対象項目の識別を追加する場合は、所有者・問題の対応と内容一致を検証する。初回フラグや順番をクライアントから信用せず、既存自由演習クライアントを壊さない段階移行を計画する。

## APIと整合性の要件

`POST /api/practice` を拡張する。既存の `qid / judgement / pressedWord / clientAttemptId` を維持し、日替わりセットへの解答を明示する任意の `dailySetItemId` を追加する。ユーザーIDは認証コンテキストから取得する。

- 同一ユーザー・同一 `clientAttemptId`・同一内容は、最初に確定した解答結果を返す。FSRS・イベント・セット進捗を再更新しない。
- 同じIDで内容が異なる場合は409。比較対象に `dailySetItemId` の有無と値、追加するモード・復習回等の文脈も含める。日替わり解答を自由演習として再送することを同一内容とみなさない。
- 新規解答では、履歴・習熟状態・イベント・必要な日替わり進捗・再送用結果の確定を一つのトランザクションにする。途中失敗なら全部を取り消す。
- 新規の日替わり解答は、所有者・問題ID一致・当日の日付・対象外でないことを検証する。日替わりセットの具体的な更新は日替わりセットIssueと接続する。
- 保存済み解答の同内容の再送は、日付が変わっただけでは拒否しない。初回に受理されなかった前日セットへの新規解答は拒否する。
- 結果には確定解答ID、判定、直前の判定、復習状態・期限、成立イベントを含める。初回解答の直前判定は `null`。大きな整数のIDをJavaScriptの数値精度で欠損させない。
- 日替わり進捗を応答に含める場合、再送で返る過去のスナップショットと現在の進捗を区別する。クライアントは最新セットを別途取得して表示する。
- 再送結果を履歴削除後もどう識別するかを計画に含める。履歴・イベントを集計対象から消すことと、保存済み解答の再実行を防ぐことを混同しない。
- 既存クライアントの必須フィールドと成功ステータスを壊さず、Hono RPC型とフロントの呼び出し側を合わせる。既存自由演習が日替わり進捗を自動更新しないことを守る。

HTTPの詳細な応答型・エラーコード、トランザクションを共有するリポジトリの契約、初回状態がない場合のロック方法は実装計画に記載する。クライアントが日付変更・権限エラー・入力ミス・再試行可能な通信失敗を区別できることが必要。

## 既存データの引き継ぎ

- 過去の解答履歴をユーザー・問題ごとに時系列に再生してFSRSの初期状態を作る。同時刻の解答は独立履歴IDなどの安定した順序で処理し、再実行でも結果を変えない。
- 既に解答済みなのにFSRS記憶情報がない状態を、未学習として黙って初期化しない。既存実装はこの場合にエラーを返す。
- 新しい解答と移行処理が競合しても、移行が新しい状態を上書きしない。対象範囲・完了位置・再開方法・切替時点・失敗検出を計画する。
- 過去のイベントを後付けしない。初正解の判定では過去の正解履歴を参照し、導入後の最初の正解を全員の「初正解」にしない。
- 成果イベントの記録開始時点を成長画面へ伝える。解答回数などの既存履歴集計と、導入後のイベント集計は収集範囲が違う。
- 解答履歴が存在しないのに「解答済み状態」があるなど、再現できないデータは件数と識別情報を報告し、推測で記憶モデルを捏造しない。
- マイグレーションは新規追加し、既存の適用済みSQLを変更しない。本番適用は別作業。検証と復旧の手順を含む移行計画を成果物にする。

## 受入条件

- 同一解答の再送・同時再送で、履歴・FSRSの解答数・イベント・進捗が一回分に留まる。
- 同一秒・同一問題への異なる解答IDは両方保存され、順序に沿って状態が更新される。
- 同じIDで問題・判定・押した位置・セット項目を変えると409になり、副作用がない。
- 不正解とスルーは再学習となり、1分後の正解で長期復習へ進む。期限前の正解も更新される。
- 初正解・リベンジ・復習成功が上の定義で成立し、再送で増えない。
- 保存途中の障害では履歴だけ・状態だけ・イベントだけが残らない。
- 過去に正解済みの問題を導入後に正解しても初正解イベントにならない。移行を再開・再実行しても新規解答を失わない。
- 自由演習で日替わりセットの問題を解いても、セットの完了数は変わらない。
- 定着推定が時間経過で下がるケースを扱える。
- 初回50で不正解→同日20で正解した場合、20は押し位置集計の対象外と識別できる。翌日の初回30で正解なら30は対象になる。
- 同日のモード切替・中断再開・別端末でも初回の扱いが変わらず、同時送信で初回が二つ生じない。
- 当日初回に正解し押し位置0なら対象、正解でも位置が-1/nullなら対象外。再送で順番や対象判定が変わらない。

## 依存関係・対象外・検証

FSRSの既存作業の取り込みと安全な初期化を先行する。日替わりセットへの更新部分は「日替わりセットのサーバー管理」Issueと同時に整合させる。スマート復習・学習画面・成長表示はこの結果を利用する。

個人別のFSRS最適化、判定の段階追加、オフライン中の連続学習、バッジ・ランキング拡張は対象外。

リポジトリの `AGENTS.md` に従う。関連する既存テスト、`pnpm typecheck`、変更箇所のOxlint/Oxfmt、Dockerが利用できる場合の `pnpm --filter backend test:integration` を計画する。過去の資料にはPrismaの `--skip-generate` と統合テスト準備処理の不整合が記録されているため、実装時に現状を確認し、実行不能と仕様不備を区別する。テストコードはユーザーの明示的な依頼なしに追加・変更しない。不足する確認は上記の具体的な振る舞いに対応付けて報告する。
