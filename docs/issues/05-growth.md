# 学習の成長を6指標で表示し、確定した成果を控えめに演出する

> GitHub Issue: [#317](https://github.com/woodnx/iQbe/issues/317)。Q17〜Q20の改訂内容をGitHubへ反映・照合済み。

## 背景と到達点

iQbeで「何問解いたか」に加え、「以前できなかった問題ができた」「復習に成功した」「定着が見込まれる」を伝える。学習量や連続日数の競争より、知識の獲得・定着を主役にする。

期間内の活動と現在の学習状態を分け、数字の意味を説明する。初期リリースでは6指標と既存の学習量グラフを使う。定着推定の過去の推移を後から復元する機能、バッジ、ランキング拡張は含めない。

## 指標の定義

| 項目                                | 種類   | 定義                                                                    |
| ----------------------------------- | ------ | ----------------------------------------------------------------------- |
| `attempts` 解答回数                 | 期間内 | 保存された解答の件数。同一解答の再送は増やさない                        |
| `uniqueQuestions` 解いた問題数      | 期間内 | 解答した異なる問題IDの数。同じ問題を5回解いても1問                      |
| `revengeSuccesses` リベンジ成功回数 | 期間内 | 直前が不正解またはスルーで、今回正解したイベント数                      |
| `reviewSuccesses` 復習成功回数      | 期間内 | 解答直前に復習期限が到来していた問題への正解イベント数                  |
| `reviewDue` 復習待ち問題数          | 現在   | 現在、復習期限が到来している有効な問題数                                |
| `retainedQuestions` 定着推定問題数  | 現在   | 評価時点から30日後の想起確率90%以上、かつ長期復習段階にある有効な問題数 |

- 正解・不正解・スルーすべてを解答回数に含める。異なる解答IDの実際の解答は、別端末から同じ問題に届いた場合も別の解答とする。
- リベンジ成功・復習成功は同日・自由演習・スマート復習・日替わりセットのいずれでも成立する。同じ解答で両方成立してよい。両者を足して「成功した問題数」と表示しない。
- 同日に不正解と正解を繰り返せば、条件を満たすイベントも繰り返し発生する。回数と異なる問題数を混同しない。
- 復習成功には1分後の解き直しも含む。「翌日も覚えていた」「定着した」と同義にはしない。
- 定着推定は現在の時刻で計算し直す。DBに保存された過去の `RETAINED` 判定を単に数えない。永久習得や実測正解率とも区別する。
- 問題削除時は既存と同様に履歴・習熟状態を削除し、新しい成長イベントも集計から除く。過去の集計が減ることを説明する。日替わりセットに残る対象外の情報は成果として数えない。

## 期間・データ収集範囲

- 初期表示は週。日・週・月を切り替えられる。
- JSTの暦日、日曜始まりの暦週、暦月を使う。直近7日・30日ではない。
- 対象期間は `[開始時刻, 次期間の開始時刻)` とし、画面に具体的な日付範囲を示す。現在進行中の期間であることが分かるようにする。
- 期間切替は期間内の4指標と学習量グラフに適用する。「現在の復習待ち・定着推定」の2指標は現在値のままであることを区別して表示する。
- 過去の解答履歴は学習状態の初期化と既存の解答数集計に利用する。過去の成長イベントは後付けしない。
- 成長イベントの記録開始時点を返し、開始前を含む期間では「リベンジ・復習成功は○月○日以降の記録」と示す。過去に成功がなかったという意味の0と誤解させない。
- 初正解は過去の正解履歴も参照して判定し、導入後の最初の正解という意味にしない。

## APIと画面

`GET /api/analysis/learning/summary?period=week` を追加する。省略時week、許可する期間はday/week/month。認証ユーザーの指標だけを返す。

- 応答は6指標、期間の開始・終了、現在値の評価時刻、イベント記録開始時点を表現できること。
- `practice` の保存トランザクションで確定したイベントを集計する。ブラウザが演出を再生した回数から集計しない。
- 現在の復習待ち数は `next_review_at <= 現在時刻` の問題数を維持する。スマート復習の「当日中が期限の全対象」は未来の時刻も含むため、件数が一致するとは限らない。画面では「現在の復習待ち」と「今日の復習対象」を区別する。
- 定着推定は既存の `ReviewService.estimateRetention` 等の契約を利用する。履歴から毎回FSRSを全再生せず、保存済みの記憶状態を使う。初期化不足・不正状態を黙って定着/未定着と捏造しない。
- 多数の問題の現在値を計算する際のクエリ回数と負荷を見積もり、必要なら現在値の鮮度を明示したキャッシュ等を計画する。根拠のない応答時間の保証は置かない。
- ホームから成長画面へ進める導線を設ける。ホームの「今日の5問」を主導線とし、既存の演習状況・ランキング・履歴導線を維持する。
- 既存の7区間の正解/不正解/スルーの積み上げグラフを再利用し、日・週・月の選択を揃える。棒から該当期間の履歴へ進める既存挙動も維持する。
- 0件、読込中、取得失敗を区別する。取得失敗を全指標0と見せない。

## 後続の押した位置表示に備える要件

将来の「直近に押した位置」「平均で押した位置」は、ユーザー・問題・JST日付ごとの最初の保存済み解答が正解だった場合の、有効な押し位置だけを使う。自由演習・今日の5問・スマート復習を同じ解答順として扱う。同日の2回目以降は、不正解からの解き直しかどうかにかかわらず対象外。翌日の最初が正解なら再び対象になる。

- 直近は対象条件を満たす解答のうち最新の位置、平均は同じ対象集合の押し位置の算術平均とする。解き直しの正解で直近値を上書きしない。
- 例：初回50で不正解→同日20で正解した20は対象外。後日の初回30で正解した30は対象。初回0で正解は有効な対象とする。
- `pressedWord` の現在の単位は表示済み問題文のUTF-16コード単位数。-1/nullは位置不明なので、正解でも平均の分母や直近値に含めない。
- 対象がない場合は0という実測値にせず、データなしとして表現する。既存履歴のモード・学習回が不明な場合は推測で復元せず、日別初回の判断可能性を別に扱う。
- #314/#315/#308/#316 で今回、日別初回や学習文脈の識別・元の押し位置の保存を行う。表示API、問題文上の位置表示、平均の可視化は後続であり、初期の6指標へ追加しない。
- この選別を既存の6指標・成長イベント・FSRSへ流用しない。解き直しも解答回数に含め、定義を満たすリベンジ成功・復習成功は従来どおり数える。

## 成果の演出

- 通常正解には短いフィードバック、`FIRST_CORRECT` には初めて正解した表示、`REVENGE_SUCCESS` にはリベンジ成功の表示を付ける。イベントの成立判定をフロントで再実装しない。
- 複数のイベントが同時成立したときは一つの短い表示へまとめられるようにし、連続する長いアニメーションで次の問題を妨げない。
- 日替わりセットの結果は、そのセットに属する確定解答の成果をサーバーから取得する。別端末の解答も含め、自由演習の成果を混ぜない。解答IDとセットの対応を保存・集計できるよう解答保存/日替わりIssueと調整する。
- 今日のセットが全問正解になったら、完了数とそのセットでの復習成功等をまとめる。削除で全問対象外になっただけでは達成演出を出さない。
- 同じ確定解答ID・セット完了を、通信再送や再描画で何度も演出しない。結果の再閲覧は可能にし、演出済み状態と保存済みの学習成果を分ける。
- ブランドの青、成功の緑、特別達成の金、知識の発見の紫を参考にするが、色だけで意味を伝えない。文字やアイコンを併用する。
- `prefers-reduced-motion` などの動きの抑制に対応する。新しい効果音は初期必須にせず、追加する場合は無効化できるようにする。
- 不正解を罰する表現、連続日数を失ったことへの警告、ランキングやポイントの追加は行わない。

## 受入条件

- 同じ問題を不正解・正解・正解で3回解くと、解答回数は3、異なる問題数は1となる。再送しても増えない。
- 初回不正解の1分後に初めて正解した場合、初正解・リベンジ・復習成功が同時成立し得る。それぞれの件数と画面表示が一致する。
- 期限前の正解は、学習状態は更新するが復習成功には数えない。
- 日曜0時、月初0時、日付変更の境界で、前後の期間に二重計上・取りこぼしがない。
- 日/週/月を変えると期間内の指標とグラフが変わり、現在値の2指標は現在の同じ定義で表示される。
- 時間経過で定着推定が下がる問題を、保存済み状態だけを理由に定着として数え続けない。
- 記録開始前を含む期間は、イベント集計の対象が導入後に限られることを表示する。
- 問題削除により該当する履歴・イベント・現在値が集計から除かれる。日替わりの対象外を成功に数えない。
- 再送・再読み込みで同じ成果を多重計上せず、演出も繰り返さない。動きを抑制した設定でも内容が伝わる。
- 他ユーザーの成果を取得できず、0件と取得エラーを見分けられる。

## 現在地・依存関係・検証

2026-11-16時点では6指標のAPI・成長イベントは未実装。既存の分析は `packages/backend/src/routes/analysis.ts`、`src/interfaces/infra/AnalysisQueryService.ts`、JST期間計算は `src/plugins/day.ts`、画面は `packages/frontend/src/pages/home.tsx`、`src/features/activity/components/ActivityStatus.tsx`、`src/hooks/useUserStatus.ts` を参照する。

既存ランキングの比較期間には前週比較としてそのまま流用できない実装がある。今回の指標にランキングの差分計算を流用せず、ランキング修正もこのIssueへ混ぜない。

「解答保存へのFSRS接続・成長イベントの確定」を前提とする。日替わりの結果取得は日替わりセットIssue、表示への接続は学習画面Issueと分担する。既存の学習量グラフのAPIは `GET /api/analysis/status/:date/:period` を再利用する。

過去の定着推定スナップショット保存、定着推移グラフ、バッジ、ランキング拡張、ジャンル自動分類、押した位置の表示を含む早押し詳細分析、オフライン同期は対象外。ただし上記の識別情報を今回の解答記録へ残すことは対象に含む。

関連する既存の分析・日時境界テスト、`pnpm typecheck`、変更箇所の静的解析・整形、画面と動き抑制設定の確認を行う。`AGENTS.md` に従い、新規のテストコードは明示依頼がある場合に限って作成し、不足する確認を具体的に報告する。
