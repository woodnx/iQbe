# 今日の5問をサーバーで確定し、全端末で進捗と再出題を共有する

> GitHub Issue: [#308](https://github.com/woodnx/iQbe/issues/308)。Q17〜Q20の改訂内容をGitHubへ反映・照合済み。

## 背景と到達点

iQbeの主導線として、一日最大5問に取り組み、全問に正解するまで解き直す日替わりセットを提供する。同じアカウントの全端末で、当日の問題・初回出題順・再出題の順序・進捗を共有する。端末ごとに別のセットを生成しない。

サーバーDBを唯一の正本とする。固定するのは選出された問題と初回順序であり、不正解・スルーに伴う再出題と完了はサーバーで更新する。「当日の完了」は長期的な「定着推定」とは別である。

## 対象と選出ルール

- 認証ユーザーが所有する全問題が対象。初期は問題集・タグによる絞り込みや問題数の設定を追加しない。
- サーバー側のJST日付ごとに一つ。復習期限は実際の時刻で比較し、日付キーと混同しない。
- 期限到来の復習3問＋未学習2問を基本とする。復習不足なら未学習で、未学習不足なら期限到来の復習で補う。
- 復習は期限が古い順、未学習は無作為。重複なしで最大5問。期限が同じ場合も一意に順序を定められるよう実装計画に規則を記載する。
- 未学習はそのユーザーの解答履歴がない問題。既存状態行の有無だけで、移行前の解答済み問題を未学習と誤分類しない。
- 期限前の学習済み問題では穴埋めしない。候補が1〜4問ならその分だけ。
- 候補0問ではセットを確定しない。「今は対象なし」を返し、後で問題追加・期限到来があれば同日でも作成できる。
- 1問以上で確定したセットは、当日中の新規問題追加・期限到来・習熟変化があっても増やしたり作り直したりしない。

## 開始・解答・再出題

- 初回の問題順はセット作成時に確定・保存する。選出理由（復習・未学習）も作成時点の情報として保存する。
- 未解答の問題を初回順に出題する。不正解・スルーは未完了のまま再出題対象に残し、他の未解答問題を挟んで短期の期限到来後に再出題する。
- 正解した項目だけ完了する。完了数は解答回数ではなく正解済みの有効項目数。
- 出せる未解答問題がなく、再出題がすべて待機中なら「待機」と次の出題可能時刻を返す。全問完了と誤表示しない。
- 再出題の期限・優先順もサーバーで管理する。フロントの配列操作や端末の時計を正本にしない。
- 一度完了した項目は、別端末の後から届いた不正解では未完了へ戻さない。
- 別端末からの異なる解答IDは、同じ項目でも実際の解答として履歴・FSRSに反映する。完了は一回だけ。重複再送は一回の解答として扱う。
- 自由演習・スマート復習の正解は日替わりセットを完了させない。逆に、それらの演習で長期の復習期限が延びたために、日替わりセットの未完了解き直しが何日も待機にならないよう、セットの再出題予定を独立して管理する。
- 別端末の変更は次の取得で反映する。リアルタイム配信は初期必須ではない。

## 押した位置の集計に備えた解答の区別

今日の5問の解き直しでも、#314 と同じ日別初回の識別を記録する。初回はユーザー・問題・JST日付ごとの最初の保存済み解答であり、自由演習とスマート復習も同じ順序に含む。セットの開始・再開や別端末への移動では初回へ戻さない。

初回の解答が正解かつ押し位置が有効な場合だけ、将来の直近・平均の押した位置の集計対象にする。不正解・スルー後の正解、または同日2回目以降の正解は対象外だが、セット完了・履歴・FSRS・既存定義の成長イベントには反映する。この識別と日替わり進捗を解答保存と同時に確定し、再送で重複させない。押し位置の表示自体は後続。

## 日付変更と問題削除

- JSTの日付が変わったら今日の新しいセットに切り替える。昨日のセットへ新たな解答は保存しない。
- 昨日の未完了セットを記録として残し、個々の問題の学習状態・復習期限を消さない。今日の採用は通常の選出ルールに従い、昨日の全問を強制的に移し替えない。
- 昨日すでに保存された解答の同内容の再送は、日付が変わっても元の確定結果を返す。未保存の解答とは区別する。
- 問題削除・アクセス不可の項目は対象外にし、代わりの問題を補充しない。確定時の位置と対象外になったことを把握できる情報を残し、削除された問題本文は返さない。
- 有効な残りの問題が一つ以上あり、その全問に正解したらセット完了。全問対象外なら「対象なし」であり、達成扱いにしない。
- 5問中1問が削除された場合は4問が有効な分母。完了済み問題が削除された場合も有効な分母・分子から除く。完了や削除で未完了項目を誤って消さない。
- 問題の既存物理削除と外部キーの連鎖削除を調査し、日替わり項目を丸ごと失う設計にしない。

## 必要なAPI契約

- `PUT /api/daily-sets/today`: 当日のセットがあれば返す。なければ対象を選び確定する。候補0問では永続セットを作らず、その状態を明示する。
- `GET /api/daily-sets/today`: 読み取り専用。GETだけで新規セットを生成しない。未作成・確定済み・有効対象なしをクライアントが区別できる応答にする。
- 解答は既存 `POST /api/practice` に `dailySetItemId` を付ける。日替わり専用の別履歴保存経路を作らない。
- 取得結果はセットID、JST日付、確定した項目ID・問題ID・位置・選出理由、各項目の未完了/完了/対象外、有効な完了数と総数、出題可能/待機/完了/対象なしの状態、次の出題項目・待機期限・サーバー時刻を表現できること。
- セットIDと項目IDを用いて対象ユーザー・問題の一致を検証する。他ユーザーの項目、問題ID不一致、対象外の項目、期限切れの日付を拒否し、履歴などの副作用を残さない。
- 問題本文は既存 `/api/quizzes/by-ids` を利用できる。同APIが削除・アクセス不可の問題を除外するため、ID数の差で進行不能にならないよう整合させる。
- 初回の同時PUTは `(user_id, date)` の一意制約とトランザクション等で一つに収束させる。項目の位置・問題IDの重複をDBでも防ぐ。
- 日付判定と状態更新の基準時刻を一リクエスト内で揃える。処理途中に午前0時をまたいでも、日付キーと検証が食い違わないこと。

未作成GETのHTTPステータス、0問PUTの応答型、エラーコード、読み取り時に対象外状態を算出するか保存するか、項目の永続モデルは実装計画で明示する。HTTP入力スキーマはコントローラー隣接、選出・進行のルールはドメイン/ユースケース、DB操作はリポジトリに分ける。

## 受入条件

- 同時に2端末から初回作成しても、ID・問題・初回順序が同じ一つのセットになる。
- 復習10問/未学習0問なら復習5問、復習1問/未学習10問なら復習1問＋未学習4問。候補3問なら3問、候補0問なら未確定。
- 0問表示後に問題を追加して開始できる。一度3問で確定した後に問題を追加してもその日は3問のまま。
- 不正解・スルーだけで一巡しても未完了。他の問題を挟み、再出題期限まで待機でき、全問正解して初めて完了する。
- 別端末で再開するとサーバーの最新進捗・次の問題を使う。片方の正解後にもう片方の不正解が届いても当日の完了は維持され、FSRSには両方が反映される。
- 自由演習の正解でセットが完了したり、セット内の短期の解き直しが何日も先送りされたりしない。
- JST 23:59と00:00でセット日付が切り替わり、過去の新規解答を拒否する一方、保存済み解答の再送では副作用が増えない。
- 問題削除後も順序・対象外の理由が分かり、補充せず残りで完了できる。全問削除は対象なし。
- 権限・項目・問題の不一致を拒否し、失敗時は履歴・状態・進捗・イベントのどれも部分更新されない。
