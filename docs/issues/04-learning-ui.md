# 今日の5問の学習画面をつなぎ、送信中の解答を再読み込み後も復元する

> GitHub Issue: [#316](https://github.com/woodnx/iQbe/issues/316)。Q17〜Q20の改訂内容をGitHubへ反映・照合済み。

## 背景と到達点

iQbeのホームから「今日の5問」を始め、解き直し・待機・中断・別端末での再開・結果表示まで迷わず進めるようにする。通信失敗や再読み込みで、保存結果が不明な解答を失ったり別IDで二重記録したりしない。

初回リリースはオンライン学習。送信中の一つの解答を復元して再送することは必要だが、通信できないまま次々に新しい問題を解く機能は後続の [#302](https://github.com/woodnx/iQbe/issues/302) とする。

## 既存実装

2026-11-16の作業ブランチ `woodnx/issue14` / HEAD `d53f14e` と未コミット作業を調査した。実装時に差分を再確認する。

- `packages/frontend/src/pages/home.tsx` と `src/routes/index.tsx` にホームがある。演習状況・ランキングなどの既存機能を維持する。
- `src/features/practice/components/PracticeSceneChanger.tsx` は既に `mutateAsync` で保存を待ち、失敗時は同一UUIDで再送する。保留解答は `useRef` にあり再読み込みで失われるため、ここを拡張する。
- 同コンポーネントは現在 `/practice` の検索条件と結び付いている。問題表示・保存・進行の再利用可能な部分と、自由演習/日替わりの違いを整理する。
- `src/routes/practice.tsx` と `src/plugins/db.ts` の `practiceSessions` は自由演習の端末内再開に使われる。日替わりセットの正本として流用しない。
- API型は `backend/rpc` と `src/utils/client.ts` のHono RPCから推論する。

## ホームと日替わり画面

- ホームの主導線として「今日の5問」を表示する。実際の対象が3問なら進捗は「0 / 3問」など、分母を正しく示す。
- 初回の開始操作でサーバーへ当日セットの確定を要求する。ホームの読み取りだけでセットを作らない。
- 当日セットがあれば「続きから」または完了状態を表示する。候補0問なら「今は対象なし」とし、後で再取得・開始できる。
- 問題と初回順序、再出題、進捗はサーバーの応答を使用する。端末で代替セットを作らない。
- 不正解・スルーでも次の未解答問題へ進み、その後、短期の期限到来を待って解き直す。正解した項目だけ完了する。
- 再出題待ちしか残っていないときは待機理由・次の出題時刻・中断導線を示す。端末側のカウントダウンは表示補助とし、出題可否をサーバーへ確認する。
- 有効な対象が一つ以上あり、その全問を正解したら結果画面。解答回数ではなく正解済み問題数で完了を判定する。
- 結果画面は当日のセットで確定した成果を表示し、自由演習・成長画面への導線を持つ。別端末で解いた分もサーバーの結果に含める。
- 削除・アクセス不可の問題は対象外になった理由と有効な分母を示す。全問対象外なら達成表示にしない。
- 自由演習は既存どおり一巡で終了する。スマート復習は当日の復習残しと当日中が期限の全対象へ取り組み、全問正解まで解き直す。20問などの取得単位を全体の完了と誤表示しない。

## 端末間・日付変更

- 画面を開く/戻る、タブへ復帰する、解答保存後、通信復帰時に最新の当日セットを取得する。常時リアルタイム配信は必要としない。
- 別端末ですでに完了した項目を次の取得で反映する。保存済み解答の再送応答に含まれる古い進捗で、最新のセットを巻き戻さない。
- 異なる端末の実際の解答は両方保存される。一方が正解した後に他方が不正解でも、当日の完了は取り消さない。習熟状態には後の不正解も反映される。
- サーバーのJST日付が変わったら今日のセットへ切り替える。前日の未完了分は今日の完了数へ引き継がない。
- 前日の保存済み解答の再送は成功結果を回収する。未保存の前日解答が拒否された場合は「日付が変わったため、この解答は保存されなかった」と説明し、今日のセットへ移動する導線を示す。
- 拒否された前日解答を、黙って今日のセットや自由演習の解答へ付け替えない。

## 送信中解答の永続化

日替わり・スマート復習・自由演習の解答保存で共通の仕組みを使う。

1. ユーザーの判定を確定したとき、一つの `clientAttemptId` と送信内容を作る。
2. 送信前に、対象アカウント、問題、判定、押した位置、必要なセット項目ID・復習回の識別、再開先・進行情報を端末へ永続保存する。保存失敗時はネットワーク送信や進行を行わず説明する。
3. 保存した内容のまま送信する。サーバーの成功結果を確認するまで次の問題へ進めず、連打も一つの解答にまとめる。
4. 応答が不明なら同じID・同じ内容を再送する。再読み込みやブラウザ終了後も送信内容を復元する。
5. サーバーが確定した当日初回/後続の識別を結果とともに扱い、再送やモード切替で独自に初回へ戻さない。
6. サーバー成功後、端末側の処理済み記録とセッション進行を整合させる。その途中で終了しても、再開時に同じ解答を新規IDで作り直したり、二問進めたりしない。

- 永続化はDexie等の既存基盤を利用できる。これはサーバーが未作成のセットを端末で生成する許可ではない。
- 通信失敗は再試行可能として残す。認証切れは同じアカウントでの再認証を案内する。権限・削除・前日日付・内容不一致などの確定エラーは無限再送せず、理由と取れる操作を示す。
- ログアウトで保留中の解答がある場合は明示する。別ユーザーには内容を見せず、そのユーザーとして送らない。同じアカウントで再開できるようアカウント単位で隔離する。明示的な破棄操作なしに保留解答を黙って消さない。
- 既存のユーザー識別子を持たないセッションを、新しくログインしたユーザーへ推測で割り当てない。移行・隔離方針を計画する。
- 同じブラウザの複数タブで再送されても、サーバーの冪等性により副作用は一回。端末側も同じ保留解答で進行を二重適用しない。
- 通信が切れたら、読み込み済みの現在問題や保留解答の説明は表示できてよいが、保存未確認のまま新しい問題の解答を続けない。

## 押した位置と当日初回の識別

初回はユーザー・問題・JST日付ごとの最初の保存済み解答であり、自由演習も含む全モード共通でサーバーが判定する。画面を開き直しただけで初回扱いにしない。スマート復習・今日の5問の解き直しで正解した場合も、押した位置を捨てずに保存し、集計対象かどうかは区別できるようにする。

現行の押した位置は表示済み文字列のUTF-16コード単位数。0は有効、-1/nullは位置不明。終了・中断時にも取得済みの押し位置を保持し、一律に-1へ置換しない。将来表示する直近・平均は当日初回に正解した有効な位置だけが対象だが、その表示APIや画面は今回作らない。

## UIの状態と責務

少なくとも、未開始、読み込み中、出題中、解答保存中、保存失敗、再出題待機、完了、対象なし、日付変更、再認証が必要な状態を表現する。表示名は利用者の言葉にし、内部IDやトランザクション等の実装詳細を画面へ露出しない。

進行ルールはモードごとに分け、問題表示・入力・保存待ちを再利用する。日替わり進捗はサーバー、自由演習/スマート復習のセッションは端末、送信中解答はアカウントで隔離した再送用記録、という責務を明確にする。

## 受入条件

- ホームから開始し、中断後に別端末で同じセット・最新進捗から再開できる。
- 不正解・スルーが残れば完了にならず、必要なら待機を挟み、全問正解で結果へ進む。
- 候補0問と全問削除を適切に説明し、空の達成演出を出さない。
- サーバー保存前に通信断、保存後に応答消失、その後の再読み込みのいずれでも、同じIDで再送し履歴・FSRS・成果を二重更新しない。
- サーバー成功から端末の進行保存までの間に閉じても、一問を二度進めない。
- 別アカウントへ切り替えても保留解答・問題・進捗を混在させず、他アカウントとして再送しない。
- 日付変更後、昨日保存済みなら結果を回収し、未保存なら理由を表示する。昨日の解答を今日の完了数へ付け替えない。
- 自由演習の検索・中断再開・一巡終了を維持し、スマート復習は全対象の全問正解まで終了しない。
- 同日の不正解後に再開・別モードへ切替して正解しても押し位置の初回集計対象に戻らず、押し位置自体は失われない。
- キーボード操作、保存中の重複操作防止、読み上げ可能な待機・失敗表示を備える。

## 依存関係・対象外・検証

「解答保存へのFSRS接続」と「日替わりセットのサーバー管理」を前提にする。共通の永続再送処理はスマート復習Issueからも使う。成果演出の表現と成長画面は「成長表示」Issueが担当し、ここではサーバーで確定した結果を渡す。

オフラインでの連続学習、全問題のオフライン保存、過去セットの再開、自由演習セッションの端末間同期は対象外。既存の検索・履歴・コレクション・ランキングを削除しない。

変更は `src/routes` で行い、必要ならルート生成コマンドを使う。`routeTree.gen.ts` は直接編集しない。関連する既存の保存待ち・再送・再開テスト、型検査・静的解析・書式検査を行い、2端末・通信断・再読み込み・ログイン切替の画面確認を計画する。`AGENTS.md` に従い、テストコードは明示依頼なしに追加・変更しない。
