# 当日の復習対象を全問正解するまで解き直すスマート復習を提供する

> GitHub Issue: [#315](https://github.com/woodnx/iQbe/issues/315)。Q17〜Q20の改訂内容をGitHubへ反映・照合済み。

## 背景と到達点

iQbeで、その日に復習すべき自分の問題をまとめて学習し、対象全問に正解するまで解き直せるようにする。過去の復習残しと当日中に復習期限を迎える問題をすべて対象にし、20問という学習対象数の上限は設けない。

ユーザーの追加指示により、旧仕様の「最大20問を一巡したら終了」を置き換える。不正解・スルーは未完了であり、全問正解まで短期の待機を挟んで繰り返す。将来の押した位置の集計で、解き直しによる正解を識別・除外できるよう記録する。

## 対象の確定と進行

- 認証ユーザーが所有する解答済み問題のうち、復習期限が開始日のJST翌日0時より前の問題を対象にする。過去の復習残しと当日中に期限を迎える問題を含み、翌日以降が期限の問題・未学習・削除済み・アクセス不可は含めない。
- 初回の出題は当日の好きな時間に取り組める。例：当日22時が長期復習の期限でも、朝からこの復習の対象にできる。不正解・スルー後の再出題には短期の待機を適用する。
- 復習期限が古い順に対象全問を選ぶ。問題数の上限で残りを黙って切り捨てない。ページ単位の取得や画面上の区切りは可能だが、その区切りを全対象の完了と扱わない。
- 開始時の対象問題IDと初回順序を確定する。開始後に別問題の期限が変化しても、その回へ自動追加せず、次に開始するときに選び直す。これは旧仕様から継続する対象固定のルールである。
- 対象0件は「今日の復習対象はありません」と表示し、空の演習を開始しない。
- 未解答の問題を初回順に出題する。正解した問題はその回の完了とし、不正解・スルーは未完了のまま解き直し対象に残す。
- 不正解・スルーは他の未解答問題を挟み、FSRSの短期の期限到来後に再出題する。初期の学習・再学習ステップは1分。
- 未解答がなく、未完了の解き直しがすべて待機中なら、待機理由と次の出題時刻、中断導線を示す。全問正解と誤表示しない。
- 有効な対象が一つ以上あり、その全問に正解したらその回の結果を表示する。完了数は解答回数ではなく、正解した異なる対象問題数。
- 全問正解を強制して画面に閉じ込めない。中断後はその回の対象・正解済み項目・解き直し予定・解答の識別を復元する。
- この回の対象は開始日を基準とする。日付をまたいで継続した場合も、開始済みの対象を黙って別の日の一覧へ差し替えず、結果を「今日の全対象を完了した」と誤表示しない。新しく開始した回は新しいJST日付で選び直す。

## 記録と他モードとの関係

- 解答は共通の `POST /api/practice` を利用し、初回・解き直しとも履歴・FSRS・条件を満たす成長イベントへ反映する。押した位置の集計から除外することと、学習記録を捨てることを混同しない。
- スマート復習であること、どの復習回・対象項目への解答か、初回と後続解答の関係を保存して後から判別できるようにする。当日初回の判定は全モード共通の保存順に基づきサーバーで確定し、クライアントの申告だけで決めない。
- 日替わりセットへの解答ではないため `dailySetItemId` は付けない。同じ問題が今日の5問にあっても、スマート復習の正解だけで日替わり進捗は完了しない。
- 途中で別端末・別モードが同じ問題を解いても、この回の対象は差し替えない。他モードの更新で長期の復習期限が延びたために、この回の未完了解き直しが何日も待機にならないよう、回ごとの再出題予定を区別する。
- 初回の出題を実際の期限より前に行った場合、FSRSには解答を渡すが、時刻ベースの復習成功イベントの条件を満たすとは限らない。既存の成長イベント定義を変更しない。
- この端末での中断・再開を提供する。全端末共通の復習セッション・途中進捗の共有は今回の追加要件ではなく、引き続き初期対象外。ただし初回/後続の解答判定や保存の整合性はサーバーで担保する。
- 再開時に削除された問題は理由を示して対象外にし、残りを続ける。全問なくなった場合は対象なしであり、達成扱いにしない。

## 押した位置のために保存する情報

将来、問題ごとの直近・平均の押した位置を表示する際には、ユーザー・問題・JST日付ごとの最初の解答が正解だった場合の、有効な押した位置だけを使う。同日の2回目以降は、解き直しの理由やモードにかかわらず除く。自由演習も含めた全モードの保存済み解答順から初回を判定し、今日の5問にも同じ基準を適用する。中断・再開・新しい復習回・別端末・別モードへの切替で初回へ戻さない。

例：初回50の位置で不正解、解き直し20の位置で正解したとき、20を押した位置の集計へ混ぜない。後日の新たな初回で30の位置に正解すれば、その30は対象にできる。履歴から問題自体を永久に除外する処理ではなく、解答ごとの区別である。

表示用APIやグラフは後続。今回は、後で確実に選別できる識別情報を保存するところまでを対象とする。過去履歴のモードや復習回は復元できないため不明として扱う。当日最初かどうかは保存済みの日時と履歴IDから安定した順序を再現できる範囲で判定し、不明な情報を推測で補わない。

## APIと責務

復習候補は `GET /api/reviews/due` 等の専用APIで取得する。日替わりセットの「現在時刻までに期限到来」と、スマート復習の「当日中に期限到来」を契約上区別する。APIの具体的なパラメーターまたはエンドポイント分離は実装計画に記載する。

- スマート復習では対象全件に到達できること。旧案の `limit=20` は学習対象の上限として使わない。取得単位に上限を置く場合は、全体の件数と続きを取得する方法を提供する。
- ページング途中の解答で復習期限が変化しても、開始時の対象を読み飛ばしたり、重複させたりしない。開始対象のスナップショットや安定した継続方法を計画する。
- 問題ID・復習期限・選出順と、その回の全対象が分かる情報を返す。候補の読み取りで履歴や学習状態を進めない。
- 問題本文は既存 `GET /api/quizzes/by-ids` を利用できる。取得の間に削除された問題を別の問題で補充しない。
- 共通の候補抽出は復習期限の境界を明示的に受け取り、日替わり側の対象範囲を今回の変更で広げない。未学習での補完はスマート復習では行わない。
- 解答APIへ復習回・モード等を追加する場合は、所有者・問題の対応・同じ解答IDの内容一致を検証する。冪等性と履歴・FSRS更新の一括保存を維持する。
- `QuizInfra` に進行規則を集中させず、復習のユースケース、進行モデル、データ取得を分ける。HTTP入力スキーマはコントローラー隣接に置く。

## 画面と受入条件

ホームまたは既存の演習導線から開始し、既存の問題表示・正誤入力・中断機能を再利用する。保存成功前に次へ進まず、送信中の解答を再読み込み後も同じID・同じ初回/後続の関係で再送する。

- 当日対象25問なら25問すべてに到達でき、20問で完了にしない。
- 前日以前の復習残しと当日22時が期限の問題を朝に対象にでき、翌日0時が期限の問題は含めない。
- 3問を不正解・正解・スルーで一巡しても完了は1/3。残り2問を待機後に出し直し、3/3になって初めて完了する。
- 保存件数と正解済み問題数を分ける。同じ問題を3回解いて正解しても、その回の完了は1問分。
- 待機中に中断・再開しても、未完了問題・次の出題時刻・解き直しの識別が失われない。
- 開始対象の取得を分割しても、途中の状態更新で取りこぼさず全問扱える。
- 別モードの正解でこの回の未完了問題を消したり、解き直しを長期の期限まで先送りしたりしない。
- 解き直しの正解は履歴・FSRS・既存定義のイベントへ反映されるが、将来の押した位置の初回正解集計から除外できる。
- 同日の最初が不正解・スルーなら、その後どのモードで正解しても押した位置の対象にならない。翌日の最初が正解なら対象に戻る。
- 2端末から初回が同時送信されても、初回と記録されるのは一つだけ。再送では順番が進まない。
- 保存失敗・再送で解答数・試行順・進捗・FSRSが重複せず、未保存で次へ進まない。
- 自分以外の問題・削除済み問題を出さず、全問対象外を達成扱いにしない。
